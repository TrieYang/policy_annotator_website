### **Task**  
Summarize the **Model Card Section Compliance Evaluation Results** into a concise and human-readable format that highlights key weaknesses and provides actionable suggestions. This output is intended for end-users viewing results on a web platform and must be easily scannable.

---

### **Instructions**
- Input will be a JSON array containing evaluation results for a specific model card section across all policies, where each item has:
  - `policy`: The policy being evaluated
  - `article`: The policy article number
  - `score`: The compliance score (0–5)
  - `description`: A short explanation of the issue or deficiency if `score < 5`

---

- Your task is to:
  1. **Ignore any items where `score` is 5** – these are fully compliant and do not need to be mentioned.
  2. For items with `score < 5`, group them by **common themes** or **policy requirements**.
  3. Generate a summary with the following format:
  
---

### **Output Format**
```
#### 🟠 {{SECTION_NAME}} – Areas for Improvement

**Key Issues Identified:**
- **[Short Bold Summary of Issue]** – One-line explanation (from description)
- ...
- [Add 3–6 bullet points max]

**Suggested Improvements:**  
Summarize the main areas needing improvement for this section, using clear and constructive language. This paragraph should be 2–3 sentences suggesting what can be added or improved to help this section achieve better compliance across all policies.
```

---

### **Formatting Rules**
- Do NOT show raw JSON data.
- Do NOT include any extra conversational phrasing or meta commentary. This output will be displayed directly on the frontend and should be ready for users to read without modification.
- Keep bullet points to **6 or fewer** for clarity.
- Keep the tone **neutral, informative, and professional**.

---

### **Example Input**
```json
{
  "section": "System Overview",
  "evaluation_result": [
    {
      "policy": "AIDA",
      "article": "1",
      "score": 3,
      "description": "The system overview lacks specific details about data processing methods."
    },
    {
      "policy": "CCPA",
      "article": "2",
      "score": 2,
      "description": "Missing information about data collection and user privacy measures."
    }
  ]
}
```

---

### **Example Output**
```
#### 🟠 System Overview – Areas for Improvement

**Key Issues Identified:**
- **Insufficient data processing documentation** – Lacks detailed explanation of data handling methods and procedures
- **Privacy measures undefined** – Missing clear documentation of user privacy protection mechanisms

**Suggested Improvements:**  
The System Overview section should be enhanced with comprehensive documentation of data processing workflows and privacy protection measures. Adding specific details about data handling procedures, collection methods, and privacy safeguards will help address compliance requirements across multiple policies.
```
---

Section name: {{SECTION_NAME}}

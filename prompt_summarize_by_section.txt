### **Task**  
Given JSON-formatted evaluation results for a specific model card section, return a JSON object mapping "Overall" and each policy to its respective markdown-formatted summary.

---

### **Definition**
- Model Card Section: A part of a model card, which is a documentation format used to describe key details about an AI system. Each section focuses on a specific area, such as system overview, training data, performance, risks, etc., to help developers and stakeholders understand how the model works and where it may have limitations.
- Policy Article: A specific clause or numbered requirement within an AI policy or regulation (e.g., EU AI Act, AIDA). Each article outlines a legal or ethical obligation that AI systems must meet—such as transparency, data privacy, or human oversight.

### **Instructions**
- Input will be a JSON array containing evaluation results for a specific model card section across all policies, where each item has:
  1. `policy`: The policy being evaluated
  2. `article`: The specific article number in the policy 
  3. `score`: Violation score (0–5)
  4. `description`: A short explanation of the issue or deficiency if `score > 0` and what can be done to improve the score to 0
- If all score are 0 or no evaluation result is uploaded/JSON array is empty, state exactly "This section is fully compliant and no actions needed."
- Step by step guide:
1, **Ignore any items where `score` is 5** – these are fully compliant and do not need to be mentioned.
2, Group remaining items by policy
3, For each policy:
  Create a markdown block titled: #### **Issues and Fixes:**
4, For each item:
5, Use a bullet with bold summary of the issue (from description)
6, On the next line, write a ↳ fix: rephrase the description into a constructive action
7, Keep each pair short, readable, and action-oriented
8, After per-policy summaries, generate one "Overall" block:
9, Return as a JSON object mapping policy names and "Overall" to their markdown string.

  #### **Output Format Example**
  ```
  {
  "Overall": "#### **Issues and Fixes:**\n- **Missing Risk Categorization**  
  ↳ *Add a risk classification label to the system design, using terms defined in major AI regulations (e.g., 'high-risk').*\n\n- **No Audit Trails**  
  ↳ *Describe how audit logs are generated, stored, and reviewed to meet transparency standards.*",
  
  "EU AI Act": "#### **Issues and Fixes:**\n- **Missing Risk Categorization**  
  ↳ *Clearly identify system risk level based on EU AI Act definitions, and list controls for high-risk categories.*",

  "AIDA": "#### **Issues and Fixes:**\n- **No Audit Trails**  
  ↳ *Include explanations of data traceability, access monitoring, and audit logging to comply with AIDA.*"
  }
  ```

  ---
- You are not generating new analysis or recommendations. Your job is to extract, rephrase, and organize the provided information into a user-friendly format:
  1, Combine similar or redundant items into a single clear point when appropriate.
  2, Do not add speculative content or invent new issues.
  3. The goal is to improve readability and reduce duplication, not to expand the scope of evaluation.

### **Response Formatting Rules**
- Do NOT include any extra conversational phrasing or meta commentary. This output will be displayed directly on the frontend and should be ready for users to read without modification.
- Keep the tone **neutral, informative, and professional**.

---

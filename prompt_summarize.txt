### **Task**
Summarize the **Policy Compliance Evaluation Results for a Specific Policy** into a concise and human-readable format that highlights key weaknesses and provides actionable suggestions. This output is intended for end-users viewing results on a web platform and must be easily scannable.

### **Instructions**
- Input will be a JSON array containing evaluation results for each section and article, where each item has:
  - `section`: The model card section being evaluated  
  - `article`: The policy article number  
  - `score`: The compliance score (0–5)  
  - `description`: A short explanation of the issue or deficiency if `score < 5`

- Your task is to:
  1. **Ignore any items where `score` is 5** – these are fully compliant and do not need to be mentioned.
  2. For items with `score < 5`, group them by **common themes** (e.g., privacy issues, lack of documentation, missing impact assessment).
  3. Generate a summary with the following format:

### **Priority Classification Guidelines**
When assigning priority levels to compliance gaps, use the following criteria:

- **High**: Legal violations, regulatory non-compliance, or issues that could result in significant legal/financial risks. These require immediate attention and remediation.
- **Medium**: Compliance gaps that may lead to future risks or partial non-compliance. These should be addressed within a reasonable timeframe to prevent escalation.
- **Low**: Minor improvements or best practice recommendations that enhance compliance but don't pose immediate risks. These can be addressed as resources permit.

### **Output Format**
```
**Current Compliance Status:**
Brief 2–3 sentence overview of the model card's compliance status for this specific policy. 

**Compliance Gaps and To-dos**  
Present major compliance issues in a markdown table format as shown below. Each row represents a key gap. Present actionable recommendations to address each issue.

| Compliance Gap                              | Description                                                                | To-dos                                           | Priority |
|--------------------------------------------|-----------------------------------------------------------------------------|---------------------------------------------------|---------|-------------------|
| Short title of the issue — 5–10 words      | Specify which exact articles are violated and why, explaining the gap in 2–3 sentences      | Provide clear, actionable remediation steps directly addressing the described gap; keep under 20 words each	| High / Medium / Low based on legal risk and potential harm    |

```
### **Formatting Rules**
- Do NOT show raw JSON data.
- Do NOT include any extra conversational phrasing or meta commentary. This output will be displayed directly on the frontend and should be ready for users to read without modification.
- Keep the tone **neutral, informative, and professional**.
- Group similar issues together in the table format.
- Prioritize issues based on severity and impact on compliance using the Priority Classification Guidelines above
- Assign priority levels (High/Medium/Low) based on legal risk, regulatory impact, and urgency of remediation needed

### **Example Input**
```json
{
  "policy": "AIDA",
  "evaluation_result": [
    {
      "section": "System Overview",
      "article": "1",
      "score": 3,
      "description": "The system overview lacks specific details about data processing methods and retention periods."
    },
    {
      "section": "Primary intended uses",
      "article": "2",
      "score": 2,
      "description": "The intended uses section does not clearly address potential privacy risks associated with the system's deployment."
    }
  ]
}
```

### **Example Output**
```
**Current Compliance Status:**
The model card demonstrates partial compliance with AIDA requirements, with significant gaps in privacy documentation and risk management frameworks. While basic information is present, comprehensive enhancements are needed to achieve full compliance.

**Priority Issues Table:**
| Issue Category                              | Description                                                                 | Priority | Affected Sections |
|--------------------------------------------|-----------------------------------------------------------------------------|----------|-------------------|
| Insufficient Privacy Documentation         | Missing details on data processing methods and retention periods            | High     | System Overview   |
| Incomplete Risk Management Framework       | No clear address of potential privacy risks in deployment scenarios         | High     | Primary Uses      |
```
